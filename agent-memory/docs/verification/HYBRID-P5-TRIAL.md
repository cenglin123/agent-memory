## 4. 发现（按影响排序）

1. **合成 held-out 显著高估真实效果。** 同一系统在三份合成集上首命中 0.907–0.979，在真实 7 天数据上 0.06–0.31。主因不是融合常量，而是真实语料形态：工具输出占绝大多数、同一提示词在大量 worker 会话中重复，正确轮次被大量近似候选淹没。
2. **单元策略应区分对话与工具 I/O。** 只嵌入对话文本（D）相对全量（C）：单元数降 26×、重放快 52×、延迟降 5–12×、recall 与首命中均更高；代价是仅存在于工具输出中的事实（例如报错信息、子代理写入的报告）只能靠词面找回。
3. **扫描预算造成排序偏差。** 默认 32 MiB 每源预算在真实体量下截断，且按来源路径顺序推进，排序靠后的会话（含本窗口最重要的主会话）完全未被检索。向量路径应覆盖全部单元，词面扫描应按时间倒序或基于索引，而不是按文件名顺序线性扫描。
4. **门控常量在真实负例上失效。** 主题外查询 1/4–3/4 返回命中。门控常量在合成开发集上标定，需真实负例集重新标定。
5. **部署缺口：生产安装下语义永远降级。** 二进制从可执行文件祖先目录查找 `scripts/recall_embedding.py` 或 `assets/scripts/recall_embedding.py`；`61-install-agent-memory.ps1` 只安装 exe 到 `<user-home>/.agent-memory/bin/`，未安装辅助脚本，`replay`/`memory_search` 报 `script_unavailable`。本次试采改用套件目录内同哈希的分发物二进制规避。
6. **OpenCode Archive 适配缺口**（路径 A、B）：opencode JSONL 无法 replay；V2 SQLite replay 外键顺序错误；`semantic::units` 无 OpenCode 投影器（只能整条记录回退）。
7. **嵌入成本**：全量重建约 16 单元/s；工具输出全量嵌入时 7 天数据需 1.5 h，增量重放必须复用未变单元的向量。

## 5. 结论与建议

- **不调整融合/门控常量**：样本显示主要矛盾在单元策略、扫描预算与适配器，而非常量；在这些结构问题解决前调常量会过拟合当前样本。
- 建议另立后续计划，按优先级：① 61 安装辅助脚本（或在配置中显式给出脚本路径）；② OpenCode Archive 适配（V2 SQLite replay 顺序修复 + 对话/工具分离的 OpenCode 投影器）；③ 单元策略：对话文本入向量，工具 I/O 仅词面；④ 检索预算：向量全量、词面按时间倒序/索引；⑤ 用真实数据构造并隔离的评估集重新标定门控（真实数据不得外发给其他模型，标注需在本机或获授权的通道内完成）；⑥ 增量重放复用向量。
- P0 冻结指标在真实数据上**未达成**，P5 记为「试采完成、生产验收未通过」，计划保持 active，待后续计划完成后再做第二次试采。
