# 统一混合检索 P0 指标基线

状态：冻结（P0）。P3/P5 如需调整，必须在 checkpoint 记录原因、样本与新旧值；未记录不得改动。
绑定代码：`agent-memory/src/recall/semantic/metrics.rs`。

## 冻结阈值

| 指标 | 口径 | 阈值 |
|---|---|---|
| recall@5 | held-out 查询集中，正确证据出现在前 5 条结果的比例 | ≥ 0.80 |
| 首命中轮次正确率 | 第一条命中回读到正确会话/轮次的比例 | ≥ 0.90 |
| 回读成功率 | 返回 ref 中 `memory_read` 成功的比例 | = 1.00（100%） |
| p95 单源检索延迟 | 单源一次 `memory_search` 的 p95，毫秒 | ≤ 20000 ms（20 s） |
| 索引体积比 | 检索索引总字节 / 源文本字节 | ≤ 3.0 |
| 量化 | 允许 f16/int8 等量化进入上述体积预算 | 允许 |

## 口径说明

- **recall@5**：按 held-out 标注的 `hit_id`（或等价的 source/round 证据）计数；同义、跨语言和长会话样本都计入分母。
- **首命中轮次正确率**：命中后必须能回读到标注轮次；只命中会话但轮次错误记为失败。禁止用孤立向量片段冒充轮次。
- **回读成功率**：`memory_read` 返回 `ok=true` 且 `range_sha256` 与 ref 一致才算成功；`REF_*`、预算截断和空段均为失败。
- **p95 延迟**：按单源计时，不把多源合并、排队或 MCP 传输时间摊入；冷启动单独记录，不混入稳态 p95。
- **索引体积比**：`derived/generations/g<N>/retrieval/` 下全部 artifact 字节 / 被索引源文本字节。允许量化，不允许把源文本副本计入“索引”来虚报。
- **held-out 与实现集分离**：实现者构造集不得充当 held-out；P3 至少 40 条合成查询，P5 真实试采另行授权。

## 非目标

- 本文件不承诺生产环境的绝对实时性；大会话 embedding 成本、Python 辅助延迟和索引体积在 P3/P5 实测。
- 本文件不改变 KB 既有 `.meta/embeddings.sqlite` 与 `ask.py` 的权威路径。
